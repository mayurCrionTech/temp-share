Perfect. Your `whoami` output shows the exact account:

```text
tbad\a365_a_rpmayur
```

So the previous `.\A365_A_RPMAYUR` was the problem.

Use the **domain account** explicitly.

### 1. Delete the existing task

```cmd
schtasks /delete /tn "PM2 Process Monitor" /f
```

### 2. Create it under your account

```cmd
schtasks /create /tn "PM2 Process Monitor" /tr "powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Users\A365_A_RPMAYUR\PM2\pm2-monitor.ps1" /sc minute /mo 1 /ru "TBAD\A365_A_RPMAYUR" /rp *
```

It will ask for your Windows password.

### 3. Verify

```cmd
schtasks /query /tn "PM2 Process Monitor" /v /fo list
```

You should now see:

```text
Run As User: TBAD\A365_A_RPMAYUR
```

and:

```text
Schedule Type: Minute
Repeat: Every: 1 Minute(s)
```

### 4. Test it immediately

```cmd
schtasks /run /tn "PM2 Process Monitor"
```

Then wait ~10 seconds and check:

```cmd
type "C:\Users\A365_A_RPMAYUR\PM2\pm2-monitor.log"
```

---

### One important check

Before testing recovery, make sure all 3 are currently running:

```cmd
pm2 list
```

If all 3 are online, **do not run `pm2 save` again unless you intentionally want to update the saved list**.

Once the task shows `TBAD\A365_A_RPMAYUR`, we'll test by removing `ML-Clonos` and letting the scheduled task restore it.
